# Pravda-Bot v0.3.3 — stabilité Windows et authentification vérifiée

**Préversion corrective Windows x64** · succède à v0.3.2, sans modifier les releases immuables précédentes.

## Corrections apportées

- **Données locales stables** : le bureau Windows Tauri stocke par défaut `pravda.db` et `pravda_auth.json` dans le dossier **`%LOCALAPPDATA%\Pravda-Bot`**, et non dans le répertoire de lancement susceptible de varier entre un raccourci, l'Explorateur et le terminal.
- **Chemins personnalisés inchangés** : si `PRAVDA_DB_PATH` ou `PRAVDA_AUTH_PATH` sont définis explicitement, le lancement conserve ces chemins. Une défaillance de création du dossier AppData arrête le démarrage au lieu d'utiliser un emplacement incertain.
- **Tests Windows renforcés** : compilation de l'application, lancement du serveur local, simulation d'une première navigation WebView2, création d'un mot de passe local généré aléatoirement pour le test, refus de l'API sans session, ouverture du tableau de bord, déconnexion avec révocation et reconnexion.
- **Documentation de sécurité rectifiée** : l'accès au dashboard, à l'API et aux WebSockets nécessite une session authentifiée ; clarification des limites de la protection Host/Origin.
- **Script Windows** : les vérifications locales incluent désormais le formatage et les tests propres au projet Tauri.

Les correctifs de la v0.3.2 concernant `request origin not allowed` sont conservés.

## Installation et vérification

Télécharger l'archive `Pravda-Bot-v0.3.3-Windows-x64.zip` depuis cette release, **l'extraire complètement**, puis lancer `pravda-app.exe`. Cette archive est une application portable, pas un installeur MSI. WebView2 Runtime peut être nécessaire.

Fermer l'ancienne version, y compris sa console, avant le nouvel essai pour libérer le port 8080. Le serveur local doit répondre sur `http://127.0.0.1:8080/login` tant que l'application reste ouverte. Les extensions et paramètres réseau du poste peuvent affecter le comportement réel ; les tests CI ne garantissent pas un rendu GUI identique sur tous les ordinateurs.

## Migration des données existantes — lire avant le premier lancement

**Ne supprimez pas et n'écrasez pas les fichiers de données des anciennes versions.** Le nouveau dossier AppData ne récupère **pas automatiquement** une base ou un fichier d'authentification créés dans un précédent répertoire de lancement.

Si vous souhaitez conserver votre compte local et votre historique de v0.3.2 :

1. Fermez toutes les instances de Pravda-Bot.
2. Sauvegardez vos anciens fichiers `pravda.db` (et les éventuels `pravda.db-wal` et `pravda.db-shm`) ainsi que `pravda_auth.json`.
3. Si le répertoire `%LOCALAPPDATA%\Pravda-Bot` ne contient encore **aucun fichier de données**, copiez-y le jeu de fichiers cohérent provenant de votre ancienne installation.
4. N'écrasez jamais une base ou un fichier d'authentification déjà configuré dans le nouveau dossier sans disposer d'une sauvegarde contrôlée.

Autre possibilité : définir explicitement les variables `PRAVDA_DB_PATH` et `PRAVDA_AUTH_PATH` vers les fichiers de votre choix.

Cette procédure n'est pas automatique afin d'éviter toute perte ou remplacement accidentel de données.

## Sécurité et limites

L'application est une surveillance de marché et un **simulateur papier sans ordre réel**. Elle ne remplace ni la sécurité Windows ni un audit externe complet. Les tests automatisés confirment le fonctionnement du binaire et des routes HTTP, pas l'absence de toutes les vulnérabilités ou la compatibilité graphique de chaque PC. Les fonctions héritées du code Python ne sont pas toutes migrées.
